# 白银之城：波纹擦除的源码分析

分析日期：2026-11-13。对象为官方站点的桌面生产代码与实际浏览器画面。本文讨论转场机制，项目菜单采用透明底，不引入官网场景、人物或背景贴图。

## 源码定位

桌面实现位于第一方发布文件 [CA2EmTRG.js](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)，其中保留了组件名 `ShaderBackground_pc.client`。文件内包含顶点与片元程序，以及创建材质、同步纹理、调整视口和逐帧推进的代码。对应下载内容 SHA-256 为 `4b91ff77bbd3fe4cce485ad25863a4aafeba0dd979d1432134afac5bdf8f748d`。

该文件通过 [CMX2w2ws.js](https://silverpalace.elementagames.com/_nuxt/CMX2w2ws.js) 中的图形组件绘制全屏平面；场景输出之后还经过合成器和后处理。画布使用透明清屏，并随窗口大小同步尺寸和相机比例。这里是实际 GPU 绘制，不是单靠 CSS 移动页面。

公开生产文件没有附带 source map。本次结论来自直接阅读生产代码、解码其中的着色器字符串和浏览器截图；没有把压缩后的局部变量名当作原始源码命名。

## 前后两幅内容怎样接替

材质同时持有当前与下一幅内容，并额外读取法线和噪声纹理。页面状态决定内容、方向、模式与进度，逐帧渲染层据此更新材质。当前画面并非先消失后再显示下一画面，而是在同一条扰动边界两侧连续交替。

源码区分圆形模式和方向模式：前者会把三维场景中心投影到屏幕，并少量混入鼠标位置；后者以滚动方向组织擦除轴，且在画面不同位置混合纵、横向阈值。两种模式还对进度、纹理缩放和纵向偏移采用不同处理。因此截图中的边界不是一条简单上下移动的直线。

## 波纹、碎边与银色轮廓各自从哪里来

1. 基础擦除轴确定大范围推进方向。
2. 低频噪声随时间移动，打散推进阈值。
3. 法线纹理的通道值再次扰动阈值，并叠加随时间变化的强度，让轮廓形成有厚薄变化的流体边缘。
4. 屏幕导数处理亮度变化，在边界附近把原画局部转换为细碎轮廓。这是截图里人物、衣服和水纹出现银色线条的主要来源；只在边界上加一条发光线无法产生同样效果。
5. 抗锯齿混合负责边界连续性，窄带增亮和后处理再增强亮部。

上述机制均可在同一份[桌面片元程序与合成代码](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)中找到。原站的法线／噪声属于其视觉资源；项目使用独立编写的程序化扰动，不打包这些贴图。

## 应用到透明 Minecraft 菜单

| 原站职责 | 项目实现 |
| --- | --- |
| 当前与下一幅背景 | 交互前后的两张 UI 渲染纹理 |
| 滚动／定时进度 | 菜单开合、分类切换、详情展开的可打断状态 |
| 法线与噪声扰动 | 独立的多尺度程序化流动场 |
| 原画边缘提取 | 对 UI 的颜色与 Alpha 边缘提取局部轮廓 |
| 全屏合成 | 按需只处理目录或详情区域，区域之外保持当帧 UI |
| 原站画面的缩放与暗化 | 界面文字保持稳定，保留 UI 的透明度与预乘 Alpha |

官网在部分边缘与暗化路径中会写入不透明颜色；直接搬用会遮住游戏世界。项目需要独立处理 Alpha：只混合 UI 自己的前后帧，世界颜色、相机与深度都不参与擦除，也不铺设黑色背景。

分类切换采用前后内容连续混合；发生新输入时，以上一次已显示结果为新的起点，避免快速切换跳回旧页面。按键定位保持即时响应，专用目录转场期间暂不接收物品点击，防止画面与槽位不一致。关闭动效后直接提交最终状态。渲染目标随窗口调整并在关闭时释放，着色器空闲时不增加整屏后处理。

2026-11-14 修正：保留同一份原始波纹着色器，恢复 420ms 内容／详情时序与 280ms 关闭时序；跨页面转场不再使用 180ms。新页面的 CSS 和字体发布完成前固定进度为零，保留旧 UI，准备完成后完整播放。Esc 返回页面反向擦除，原生导航立即执行。

项目源码对应：[`AuiInkTransition`](../client-ui/src/main/java/com/teamlifebind/clientui/AuiInkTransition.java) 保存可打断的进度与区域，[`AuiInkEffect`](../client-ui/src/main/java/com/teamlifebind/clientui/AuiInkEffect.java) 管理 GPU 前后帧，[`menu_ink.fsh`](../client-ui/src/main/resources/assets/tlb_aui/shaders/core/menu_ink.fsh) 实现独立的流动阈值、导数轮廓和预乘 Alpha 合成。导航及详情动作由 [`AuiMenuPage`](../client-ui/src/main/java/com/teamlifebind/clientui/AuiMenuPage.java) 绑定。

## 验证标准

- 抓取转场初始、中间、结束帧，检查不是单纯平移或淡入淡出。
- 在测试底板上检查透明区域，防止输出不透明黑底。
- 分别验证前后内容、区域外的稳定性、反复切换与缩放。
- Fabric、Forge、NeoForge 使用相同的着色器和状态机，并分别运行实际客户端。
- 滚动与导航的状态参数和 CSS 层交互另见[交互源码分析](silver-palace-scroll-study.md)。

本批已在 Fabric、Forge、NeoForge 的真实客户端分别通过上述 GPU 读回检查，并完成六类菜单、三个窗口尺寸的 54 个场景。逐帧图像、源码与运行结果的 SHA-256 保存在 `.tools/aui-client-evidence/`。[实际转场及操作说明](aui-web-ui.md)提供由原始 GPU 图像编码的演示；未打开玩家存档。
