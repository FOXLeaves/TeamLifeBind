# 0.4.0 新物品、补给与终局预告

0.4.0 在四端加入共鸣哨、应急绷带、动态补给与争夺开箱，并为首次要塞提示增加提前预告。新物品默认可用，补给默认启用动态数量；节奏与图腾预设继续默认 `CLASSIC`。四端构建、隔离启动与自动检查已通过，本文件列出确定规则与后续真人验收要求；实际结果由 [0.4.0 验证记录](gameplay-validation-0.4.0.md)说明。

Minecraft 26.3 与 Java 25 经 2026-10-12 [官方再次核验](upgrade-research.md)后沿用；NeoForge 更新至 26.3.0.71-beta，Paper 已在稳定 build 175 上完成隔离运行验证。安装与资源包更新见[安装说明](install-0.4.0.md)。连锁死亡、普通维度重生、禁复活维度旁观、队伍床和屠龙结算沿用现有规则；0.3.0 预设详见[历史玩法说明](gameplay-update-0.3.0.md)。

## 共鸣哨

| 属性 | 规则 |
| --- | --- |
| 识别 ID | `teamlifebind:resonance_whistle`；插件使用对应自定义物品标记 |
| 合成 | 无序：2 铜锭 + 1 红石，产出 1 个 |
| 使用 | 右键，标记准星指向的位置；射线最远 64 格，无命中时采用 64 格终点 |
| 持续 / 冷却 | 标记持续 12 秒；15 秒团队共享冷却 |
| 消耗 | 不消耗 |
| 可见范围 | 仅本队具比赛资格且非旁观的玩家获知标记；每队最多 1 个活动标记 |

用途是集合、集火与避险。标记保留维度信息，跨维度显示维度与坐标，并将距离显示为未知。换持有者或多名队员同 tick 使用不能绕过团队冷却；结束本局后清理标记与冷却。使用者须处于进行中的对局，存活、非旁观且属于参赛队伍。

## 应急绷带

| 属性 | 规则 |
| --- | --- |
| 识别 ID | `teamlifebind:emergency_bandage`；插件使用对应自定义物品标记 |
| 合成 | 无序：2 纸 + 2 线，产出 1 个 |
| 开始 | 右键开始 4 秒读条，记录触发手槽；不需要持续按住右键，可移动 |
| 成功 | 治疗 2 HP，当前最大 HP 为上限；消耗 1 个，开始 30 秒团队共享冷却 |
| 取消 | 再次右键、受伤、攻击、触发手槽物品变化、离线、换维度或死亡 |
| 满血 | 满血不开始；完成时已满血也不消耗或进入冷却 |

HP 2 = 1 颗心。绷带不提供吸收，不会把 ONE_HEART 预设治疗到其最大 HP 以上。血量同步开启且使用者没有同步豁免时，只产生一次团队共享的 2 HP 治疗，不按成员数重复累加；关闭血量同步或使用者有同步豁免时，只治疗使用者。每位接受治疗者仍受其最大 HP 限制。

开始读条不预先扣除绷带；成功时必须仍满足手槽、对局资格、维度与冷却条件。中断后需要重新右键开始完整读条。同一队同时最多一名成员进行绷带读条，冷却由全队共享；每位玩家同时只进行一个治疗或开箱读条。对局结束后清理未完成读条和冷却。

## 动态补给与开箱争夺

动态数量按仍具对局资格的队伍数计算：

```text
dropCount = clamp(eligibleTeams, 2, 8)
```

例如 1 / 2 / 4 / 12 支资格队伍分别计划 2 / 2 / 4 / 8 个补给。按具资格成员所属的不同队伍计数，跨维度队伍、普通维度仍可复活的暂时死亡队伍，以及已经分队且只是暂时离线的未淘汰队伍仍计入；永久淘汰或只有主动旁观成员的队伍不计入。数量与落点在预告时锁定，预告后资格人数变化不会漂移本批计划。

预告点若在部署前被新方块占用，则跳过该点，不覆盖玩家方块，也不重新选择落点。因此实际生成数量可能少于预告的计划数量。

每批补给在生成前 60 秒规划、锁定并公告落点，生成后为空 `BARREL`（桶）。用**空主手右键一次**开始 8 秒开箱；玩家需保持同维度且在箱子 3 格内，受伤、攻击、离开范围、换维度、离线、死亡或箱子失效会中断。无需持续按键。每队同时最多一名成员开箱；不同队伍可竞争同一箱，对局结束清理全部未完成读条。

读条成功才一次性填入战利品并解锁。同箱只生成一份奖励，未解锁前阻止普通打开、破坏/爆炸、自动搬运等旁路。解锁后可正常打开，其他队也能争夺已有战利品。这里只调整定时生成的补给容器，既有可携带补给船按原规则处理。

默认启用动态数量，可回退固定数量：

| 平台 | 动态数量键 | 默认 | 固定模式 / 禁用 |
| --- | --- | --- | --- |
| server | `timed-events.supply-drops.dynamic-count` | `true` | `false` 使用原 `count`；`count: 0` 在两种模式均禁用 |
| Fabric / Forge / NeoForge | `supply-drops-dynamic-count` | `true` | `false` 使用 `supply-drop-count` 固定数量；该值为 0 仍禁用 |

管理员可在大厅通过 `/tlb menu` 的“动态补给”按钮切换模式；进行中的对局锁定该设置。固定数量与动态开关在开局时保存本局快照，资格队伍数则在提前 60 秒规划时统计。大厅菜单与规则显示实际动态/固定模式、数量与关闭状态。自动地狱门、要塞提示和补给的既有开关继续生效，动态模式不会重新开启已关闭的补给。

## 新物品资源

共鸣哨与应急绷带使用原创 **32 × 32 RGBA** 透明背景像素材质，分别位于 `textures/item/resonance_whistle.png` 与 `textures/item/emergency_bandage.png`。两个模型使用 `minecraft:item/generated`，并通过各自的 `teamlifebind:item` 纹理显示独立外观。三种模组内置相同材质；插件玩家须重新下载本次更新的 0.4.0 资源包。配方和 `/tlb dev` 展示均使用对应物品识别标记及语言。生成原稿与生产资源的区别见[材质规范](item-textures-0.4.0.md)。

## 终局预告与节奏

本次在**首次要塞提示前 60 秒**增加一次公开预告，让各队能规划推进。实际坐标提示沿用原有逻辑，后续提示仍按既有间隔执行；关闭要塞提示也关闭对应预告。屠龙胜利归属不变，贡献结算和限命赛仍属于后续建议。

| 事件 | `CLASSIC` | `FAST` |
| --- | --- | --- |
| 自动地狱门 | 第 15 分钟 | 第 8 分钟 |
| 补给落点预告 | 第 19 分钟 | 第 9 分钟 |
| 补给容器生成 | 第 20 分钟 | 第 10 分钟 |
| 首次终局目标预告 | 第 29 分钟 | 第 14 分钟 |
| 首次要塞提示 | 第 30 分钟 | 第 15 分钟 |
| 后续要塞提示间隔 | 3 分钟 | 2 分钟 |

时间按 20 TPS 的对局 tick 计算，低 TPS 会延长墙钟时间；开箱 8 秒与治疗 4 秒同样按服务端 tick 计算。每批预告与奖励都须只执行一次，连续两局不得继承上局落点、读条、标记或冷却。

## 0.4.0 验收要求

1. 四端构建、共享规则回归、资源/翻译检查、启动与新配方加载；配置缺省、旧 count=0、动态开/关和大厅展示。
2. 共鸣哨本队可见、敌队/旁观者不可见；64 格有/无命中、12 秒过期、15 秒冷却边界、跨维度和连续两局。
3. 绷带在 2 / 10 / 20 最大 HP、血量同步开/关和同步豁免下均只结算正确治疗；满血、完成前满血、同队同时完成、30 秒边界与所有中断条件。
4. 补给数量在 0 / 1 / 2 / 4 / 8 / 12 支资格队伍输入时遵循开关与 clamp；预告后落点不漂移；8 秒前后边界、3 格边界、受伤/攻击与同箱多人争夺不重复填奖。
5. 未解锁补给容器不能经普通打开、破坏掉落或自动搬运绕过读条；成功后其他队可争已有奖励。
6. 关闭补给/要塞提示不会产生对应预告；首次预告仅一次，快慢档时间正确，屠龙结算和旧图腾救援回归。
7. 至少完成两人全流程与四人对抗试玩，再记录哨声使用率、绷带成功/中断率、补给争夺人数和对局时长。

本文件不把计划列为已通过。此前 [0.3.0 验证](gameplay-validation-0.3.0.md)与[0.2.0 验证](upgrade-validation.md)继续作为历史保留，新增交互、伤害打断与资源加载需使用 0.4.0 产物重新验收。
