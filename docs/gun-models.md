# 空投枪械原创建模与枪型辨识

七把武器采用独立编写的 Minecraft 方块三维几何。此次细化按所选 TACZ 枪型的机构布局与公开动作元信息增强辨识度：左轮弹巢、低轴枪管、折叠枪托、泵动护木、后置弹匣、转管电机和火箭头。新的尺寸、分块、旋转和 UV 均由本项目独立制作，未导入 TACZ 的模型点数组、动画关键帧、贴图或音效。

参考范围和能由官方元数据证明的事实见 [客户端表现研究](tacz-client-fidelity-research.md)。具体尺寸与分块是本项目的原创设计，未声称与原网格一比一相同。配色以黑钢、FDE 沙色、OD 暗绿和胡桃木为主，去除前一稿的青色回响导轨、晶体弹芯、陶瓷护套及虚构双枪管。

合计 479 个方块、2874 个面，每把低于 100 个方块。所有未旋转及旋转后的顶点均位于模型坐标 `[-16,32]`。握把采用原生模型允许的 `-22.5°`；圆筒、电机和左轮弹巢使用独立分块与 X 轴 `45°` 旋转，较大的圆筒截面由六个方块组合成凸八边形。枪口沿模型 `+X`，为左右手第一人称、左右手第三人称、物品栏、地面、展示框和头部设置了独立显示变换。

M95 的基础展示元数据为 `iron_zoom=1.5`，因此默认模型保留铁瞄和配件导轨，没有自动安装高倍率镜。SPAS-12 上方枪托处于收折姿态，Minigun 使用重武器式双握把与电机结构；静态模型本身没有枪托折叠或零件拆卸动作。Minigun 的独立转轮帧见下节。

三端资源使用完全一致的模型、物品模型入口及贴图。模型位于各端 `assets/teamlifebind/models/item/<物品 ID>.json`，入口位于 `assets/teamlifebind/items/<物品 ID>.json`，引用 `teamlifebind:item/weapon_atlas`。Paper 资源包使用同一组资源。

## 原创转轮帧与静态回退

`support_machine_gun_spin_00…15.json` 是由本项目 83 个方块的机枪模型独立计算的 16 个相位，每相位沿枪管 `+X` 轴转动 `22.5°`，轴心为模型的 `Y=10.4、Z=8`。38 个枪管、枪口、环架和前部轴承方块随相位转动；45 个电机、握把、供弹箱与携行部件保持原样。超过原生允许范围的元素角度通过互换 Y/Z 尺寸归一到 `0、±22.5°、±45°`，没有读入 TACZ 的帧或关键点。

机枪物品入口使用原生 `minecraft:range_dispatch`，读取 `minecraft:custom_model_data` 的第 0 个浮点值。阈值 `1…16` 分别选择上述 16 个帧，缺省值回退到原有 `support_machine_gun.json`。原生模组通过渲染用物品副本选择相位；Paper 没有相位浮点数据，继续显示 83 个方块的静态枪械。

资源加载后缓存这 16 份模型；一次绘制只选择其中一份，每帧仍为 83 个方块、498 个面，不会叠加绘制 16 份模型，也不需要在每个渲染帧解析 JSON 或生成几何。它增加模型缓存与资源加载体积；尚未测量真实客户端帧率或 GPU 占用。所有模型合计为 23 份、1807 个方块、10842 个面，这是资源全集的数量。

[四相位模型预览](images/rotor-model-preview.png) 展示 `0°、45°、90°、135°` 下的实际 JSON 几何与材质，用于检查转轮和固定部件的关系；它是本地 CPU 预览，不是游戏中的实时转动录屏。该预览随发行包提供。

## 验证范围

本地可复现作者脚本位于 `.tools/weapon-models/generate_models.py` 与 `.tools/weapon-models/fidelity_geometry.py`，前一稿保存于 `.tools/weapon-models/history/pre-fidelity/`。资源检查脚本为 `.tools/weapon-models/verify_models.py`，投影预览脚本为 `.tools/weapon-models/render_preview.ps1`，其 `.tools/weapon-models/PreviewRasterizer.cs` 以逐像素深度缓冲处理相交的方块。预览读取实际 JSON 顶点、所有旋转轴与面 UV，对最终图集进行逐像素纹理采样，已检查七枪轮廓、圆筒护套遮挡、木纹位置和四个转轮相位；这不是游戏客户端截图。游戏内握持姿态、资源包加载及武器操作以平台验证记录为准。

另以 Java 26 调用 Minecraft 26.3 的原生 `CuboidModel.fromStream`，七把基础模型与 16 个转轮帧全部成功解析：23 个模型、1807 个方块、184 个有效显示变换（每模型 8 种）。92 项左右手第一、第三人称方向检查调用原生 `ItemTransform.apply`，验证应用游戏镜像规则后枪口仍朝前。原生 `ClientItem.CODEC` 也成功解析全部 7 个物品入口，确认机枪的 16 个阈值和静态回退。依赖解析检查从这 7 个入口访问全部 23 个模型，逐字节核对三端 30 份唯一 JSON 资源。这些检查没有启动客户端或替代真人握持验证；结果保存在本地 `.tools/weapon-models/native-model-parser.log`。

枪械没有合成配方，正常对局仅通过空投获得；管理员可通过 `/tlb dev` 领取独立生成的满弹开发测试枪，见[开发者物品目录](dev-item-menu.md)。模型资源本身不提供获取途径，也不包含第三方动画或外部模型加载器依赖。
