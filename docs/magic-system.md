# 魔法玩法：300 本法术书、三槽学习与魔力

本次内容构建仍为 **0.7.0**，游戏显示版本固定 **0.1.2**，面向 **Minecraft 26.3 / Java 26**。Fabric、Forge、NeoForge 和 Paper 共用 300 项定义、学习限制、魔力、冷却和书籍抽取规则。模组内置材质；Paper 玩家需下载本批更新的资源包。

## 从第一本书开始

1. 探索尚未生成战利品的自然箱，或争夺补给空投，取得一本法术书。
2. 主手持书，**潜行右键**学习。成功消耗一本书；已经学过、三槽已满或书籍无效时不消耗。
3. 学习记录属于玩家。学习后无需持魔典即可施放，不再自动发放总魔典；把书籍交给别人不会转移已学知识。
4. 选择三槽中的法术并施放，可以空手或持普通物品。模组左下常驻魔力、三槽冷却及吟唱状态，F8 可以独立调整 HUD 位置和大小。
5. 需要换流派时，主手持遗忘之书，潜行右键遗忘当前选择。不会返还原法术书，已有冷却也不会因遗忘后重学而提前结束。

丢失总魔典后可执行 `/tlb magic focus` 补领。需要至少学会一种魔法，背包中没有总魔典；补领间隔为 10 秒。补领不提供新的学习书或魔力。

## 平台操作

| 操作 | Fabric / Forge / NeoForge | Paper |
| --- | --- | --- |
| 学习 | 主手法术书，潜行右键 | 主手法术书，潜行右键 |
| 施法 | 学会后默认 **V**，不要求持物品 | 学会后默认 **潜行＋F**，或 `/tlb magic cast` |
| 选择 | 按住 **G** 打开三槽选择页，松开确认；也可点击或使用数字／方向键 | **F** 循环切槽；旧魔典的潜行右键菜单仍保留 |
| 快速切换 | **左 Alt + 滚轮**，不要求持魔典 | **F** 循环切换，不要求持魔典 |
| 改键 | 选项 → 控制 → 按键绑定 → TeamLifeBind 魔法 | 使用、潜行和交换副手沿用可重绑的原版键 |

轮盘松开只切换，不自动施法。模组的 G 与枪械的 R 换弹分开；Paper 已移除枪械，学会魔法后 F 切槽、潜行＋F 施放；没有已学魔法时保留普通副手交换。

模组的魔力、三槽冷却、缺魔与吟唱进度使用统一卡片，轮盘显示阶位和消耗，键位提示跟随设置。小窗口布局与预览见[模组 HUD](native-hud.md)。

吟唱开始时扣除魔力并启动冷却；移动超过三格、受伤或切换所选魔法会打断当前吟唱/持续引导。已释放的领域、使魔等按各自持续时间运行，死亡、离开世界、失去使用资格和对局清理会移除其残留。取消施法不退还已经支付的魔力或冷却。`CHANNEL` 还会每 10 tick 支付 `2 + 阶位` 魔力，余额不足时停止后续脉冲。

没有活动比赛时，存活且非观察者可测试魔法与生物交互；玩家间魔法伤害只允许正式对局中有资格的敌对参赛者。投票、倒计时、观察期、淘汰和旁观状态继续受参赛资格限制。

## 魔力与伴生物品

初始魔力和上限均为 **100**。消耗魔力后先等待 60 tick，再每完整 20 tick 恢复 1 点；持续施法会重新延后恢复。魔力上限最高 **300**。药水不会溢出上限；魔力已满、上限已满或没有可遗忘法术时，相应道具保留。

| 道具 | ID | 效果 |
| --- | --- | --- |
| 奥术总魔典 | `arcane_grimoire` | 可选的旧操作入口；施放已学魔法不依赖它，不再首次赠送 |
| 魔力药水 | `mana_potion` | 右键恢复最多 40 魔力 |
| 高效魔力药水 | `greater_mana_potion` | 右键恢复最多 100 魔力 |
| 魔力苹果 | `mana_apple` | 右键使本局上限和当前魔力各增加 10，最高上限 300；局后清除成长 |
| 遗忘之书 | `amnesia_tome` | 潜行右键遗忘所选法术，释放一个学习位置 |

超位魔法需 **160–217** 魔力，初始上限不足以施放。高级法术的基础伤害、范围和表现规模上升，同时需要更多魔力、更长吟唱和冷却。位移、护盾、使魔与区域控制用途不同，不能只凭基础伤害比较强弱；实际命中受地形、护甲和各类机制影响。

## 探索与空投

只对原版 `minecraft:chests/*` 自然战利品表的容器生成事件进行一次魔法抽取。打开已经生成过物资的箱子不会重新抽取，也不会定时补满旧箱。模组只向空槽追加，已有物资不被覆盖，箱子无空槽时无法放入额外物品；Paper 在自然战利品生成事件中追加候选物资，并标记已处理容器。

每个自然箱有 **12%** 概率抽一本书。下表为每个箱子/空投获得对应阶位书的概率，已经计入自然箱的 12% 前置概率。一个阶位内均匀随机选择具体法术。

| 阶位 | 本数 | 自然箱 | 空投 |
| --- | ---: | ---: | ---: |
| 1 | 28 | 6% | 23% |
| 2 | 42 | 3.12% | 21% |
| 3 | 42 | 1.68% | 18% |
| 4 | 56 | 0.72% | 15% |
| 5 | 42 | 0.3% | 11% |
| 6 | 42 | 0.144% | 7% |
| 7 | 28 | 0.0348% | 4.5% |
| 8（超位） | 20 | **0.0012%** | **0.5%** |

每个空投必含一本书。Fabric、Forge、NeoForge 另保留一把随机枪械；Paper 已移除枪械，保留魔法和其他补给。所有学习书没有合成方式；管理员发放属于测试入口。

四端新增大型建筑的每个物资点也会独立按自然箱规则判定是否加入一本书，使用上表的自然箱概率，不采用空投的高阶权重。物资点随新区块生成，取走后不会自动补满；其中不生成枪械。

伴生物品单独抽取：自然箱在普通药水 **16%**、高效药水 **5%**、魔力苹果 **4%**、遗忘之书 **0.3%** 中抽中至多一种，与是否出书无关。空投必含一瓶普通或高效药水（各 50%），另有 **25%** 概率加入 1–3 枚苹果，**5%** 概率加入一本遗忘之书；这两次追加分别判定。

## 随机魔典开局

管理员在大厅执行 `/tlb mode RANDOM_GRIMOIRE`，或在赛制菜单切换到“随机魔典”，下一局每位参赛者得到一本随机 **1 阶**书。初始池为 28 本；发书不自动学习，玩家仍可决定保留、交换或学习。其余胜负规则沿用屠龙模式，可与已有节奏、屠龙归属、据点及边界选项组合。

每局魔法学习、魔力上限和当前魔力单独初始化。**魔力苹果成长仅本局有效**：同局断线重连保留，结束／重开对局或重新载入探索记录后上限恢复 100，当前魔力最多保留 100。旧探索文件中的苹果成长也会清除。对局结束后仍恢复非比赛探索时的学习、选槽和剩余冷却，不把上局成长带入下一局。探索记录保存于模组服务端的 `config/teamlifebind-magic.properties`，或 Paper 的 `plugins/TeamLifeBind/magic-players.properties`；重连不会重放离线前的施法特效。开发测试结束只恢复本局测试前的记录，不提前清除本局苹果成长。

## 300 种法术的机制与画面

普通部分是 **14 个学派 × 20 种基础机制 = 280 种**，另外有 **20 种超位多阶段法术**。学派包含炎、潮、霜、岚、岩、雷、辉、影、奥、森、引、时、血、灵；基础机制包含飞矢、射线、扇形、环爆、环绕、连锁、波前、旋涡、陨星、陷阱、突进、跃迁、障壁、护盾、使魔、印记、汲取、引导、回响与领域。共同执行器复用碰撞和生命周期，学派互动改变实际命中效果。

例如潮系使目标潮湿，接雷系会继续传导，霜系会凝结或碎冰；岚系推动目标并冲散持续区域；辉系净化施法者并显露敌人；时系记录连续命中并缩短自身冷却；引力系控制位置和下坠状态。

本轮为全部 **300 种法术分别登记触发规则**：首次命中、每次命中、重复击中同一目标、持续脉冲和效果结束时，可以按目标是否受伤、在空中、着地、潮湿、燃烧或远近距离触发不同动作。规则还区分命中者、自身、记录落点和最后命中者，并限制整次施法的触发次数、间隔与延迟。例如炎系环爆首次命中挑空，结束时击落最后命中者；潮系环爆首次命中净化自身，结束时击落；同为护盾，炎系重复命中可回血，潮系可恢复魔力。实际规则在服务端执行，书籍说明与目录从同一份定义生成。

这些规则复用 **24 种动作与 20 种基础机制**，每条法术有独特的触发/条件/目标/动作组合；名称、学派、颜色和伤害数值不计作机制独特性的依据。这里的 300 种差异化法术不表示 300 套完全独立的底层算法。20 种超位另外明确各阶段的持续窗口、开启和结束动作，顺序执行 3–5 阶段，如“末日红莲”的领域 → 陨星 → 陷阱，以及“星界湮灭”的印记 → 旋涡 → 陨星 → 射线 → 领域。每一本的数值、触发条件、阶段及命令 ID 见[300 本目录](magic-catalogue.md)；机器可读数据为 [magic-catalogue.json](magic-catalogue.json)。

原生客户端的第一人称吟唱会平滑抬起总魔典，并按法术运动配置轻微转动、起伏；界面关闭、换世界或失去施法状态会退出姿态。

14 种普通领域另外各有三次区域脉冲：炎领域灼烧并追加冲击，潮领域浸湿并从落点推离，霜领域冻结并缚足，岚领域挑空并推离，岩领域停住水平移动后下压，雷领域显形并打断吟唱，辉领域显形并削弱，影领域致盲并削弱，奥领域削魔并追加冲击，森领域缚足并中毒，引领域牵引并下压，时领域停动并减速，血领域凋零并削弱，灵领域悬浮并显形。脉冲仍检查合法目标、墙体遮挡和动作预算。每目标命中间隔独立计算，整次施法的总次数有限。

三端着色器现在使用 14 种学派主体几何，并结合各施法机制改变轮廓；去掉学派颜色后仍可分辨。图样与运动配置的唯一性仅是结构检查，不能代替实际效果验收；本轮加入同色 GPU 比较、三端生产渲染器像素读回及实体状态测试，见[可见性与差异化修复](magic-fixes-2026-10-18.md)。

八阶书各有原创封面，学派由叠加符文颜色区分；五件伴生物品有独立透明图标。法术在**吟唱、飞行、命中、结束**四个阶段使用各自的几何配置，300 份配置互不相同。形状包括圆、三角、方形、五芒星、六芒星、花瓣、螺旋、双螺旋、扇面、冠环、双翼和星座，可结合旋转、反向旋转、脉动、升起、折叠、绕行及向内收束。

**Fabric、Forge 与 NeoForge 的魔法视觉完全使用原创 GLSL 着色器，不生成 Minecraft 魔法粒子。** 世界深度决定遮挡，独立浮点发光缓冲绘制法阵、光束、球形格盾、旋涡、陨星与领域，再进行辉光合成。高阶增加结构与亮度，超位追加立体星环、穹顶与光柱。四阶段图样直接来自法术定义；吟唱和持续阶段由服务端同步，客户端随时间动画。无需安装参考 JAR 或额外光影包。Paper 仍使用原来的粒子表现。

障壁与使魔是临时魔法效果，不留下永久方块或生物。每个运行器限制 128 个活动阶段、单次扫描 64 个候选目标。模组每 tick 最多产生 96 条视觉场景更新，只发给同维度附近客户端；持续阶段每三 tick 刷新，结束和中断发送清理。客户端最多保留 24 个场景、每帧绘制 8 个，低帧率自动减少绘制数和体积积分步数，发光缓冲与每帧绘制面积最多各 1,382,400 像素。Paper 单独保留每 tick 1200 次粒子生成额度。画质与多人帧率仍需实际客户端试玩；实现、GPU 离屏预览与检查范围见[着色器说明](magic-shader-rendering.md)。

## 选择一项开发测试

管理员执行 `/tlb dev magic`，先选择 **14 个学派、超位或伴生物品，共 16 个分类**，再选择具体物品进入详情。每学派显示 20 本普通书，超位分类显示 20 本，伴生分类显示五件道具。浏览或点击书籍图标只打开详情，不向背包批量发书。旧 `/tlb dev` 的魔法入口也进入这个分类选择器；`/tlb dev magic <1–7>` 保留每页 45 项的平铺浏览方式，点击后同样进入详情。

详情内有两种明确操作：

- **领取一件**：只发放当前选中的一本学习书或一件伴生物品，供检查外观、正式学习和消耗流程。背包没有空格时拒绝领取并提示，物品不会掉到脚边。
- **装入测试槽 1 / 2 / 3**：直接在临时测试记录中选择该法术，不领取学习书。已有槽可替换；添加空槽须按 1、2、3 顺序，始终最多三种。每次装入将临时魔力/上限设为 300 并清理临时冷却，无需持有魔典或腾出物品格。

开始测试时先保存原来的知识、选槽、魔力、上限与冷却。测试槽不占物品栏，也不会创建临时魔典，背包满时同样可以选择法术，无需把 300 本书放入背包。

点击“结束测试并恢复原记录”或执行 `/tlb magic teststop` 后，原记录恢复，原冷却扣除测试期间已经过去的时间；临时魔力成长与所选法术不写入探索存档。退出服务器、失去管理权限或开局也会结束测试。旧版本遗留的带标记魔典会一并清理，玩家原有物品保留。测试会话中使用正常学习书或消耗品前，模组会要求先结束；Paper 会先结束临时测试，再按正常规则处理物品。

其他命令：

- `/tlb magic test <法术ID> [1–3]`：直接选定临时测试法术；省略槽位时使用当前选择。
- `/tlb magic teststop`：结束临时测试并恢复原记录。
- `/tlb magic list`：查看自身已学法术与魔力。
- `/tlb magic select <1–3>`：选择已学习的槽位。
- `/tlb magic cast`：按正常持书、学习、魔力、冷却和资格条件施法。
- `/tlb magic focus`：符合补领条件时重获总魔典。
- `/tlb magic forget`：管理员遗忘当前选择的法术，用于切换测试对象；普通玩家使用遗忘之书。
- `/tlb magic give <法术ID或伴生物品ID>`：管理员领取指定的一件正式物品，例如 `/tlb magic give apocalypse_lotus`；背包满时拒绝。

打开和领取开发者物品均验证当前管理权限。菜单图标带预览标识，不能作为有效学习书；点击领取通过物品工厂新建，拖拽、数字键交换与快捷搬运不会把预览物品当成奖励。

参考源码分析与固定提交链接见[研究记录](magic-reference-research.md)，本地 Shooting Star JAR 的渲染研究见[着色器参考记录](shader-reference-research.md)。本系统独立实现，不要求安装参考模组。实际服务器夹具与客户端输入/渲染挂点检查范围见[验证记录](magic-validation.md)；轮盘操作手感及多人视觉负载仍需真人客户端试玩。
