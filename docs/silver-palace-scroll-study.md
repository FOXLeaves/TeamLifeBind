# 《白银之城》官网：滚动、导航与转场时序分析

调研日期：2026-11-13。对象为官方桌面站 `https://silverpalace.elementagames.com/zh-cn/` 当次实际下发的代码及浏览器运行状态。用户要求移植交互与布局，游戏世界保持透出；本文不把官网背景、角色和站点业务流程作为游戏功能。

## 二、滚轮并非直接移动一个 DOM 面板

桌面路由按 `/home → /roles → /news → /features → /world` 排列。全局滚轮处理 `Yt` 先判断页面与资源是否就绪，再排除局部滚动区、弹窗和微小输入；转场进行中只继续推进当前转场。它没有把每次滚轮都换成一次新的路由跳转。[桌面事件与路由分发](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)

| 条件／输入 | 实际处理 |
| --- | --- |
| `abs(deltaY) < 15` | 忽略，不触发章节切换 |
| 目标位于 `.scroll-box` | 由局部容器处理，不触发全站切页 |
| 资格弹窗或视频弹窗打开 | 不启动章节转场 |
| 同一转场仍在进行 | 滚轮模式中把输入送回速度状态，不新建转场 |
| 新闻页需要继续自身滚动 | 先滚到对应顶部／底部；已记录触边时间时有 500ms 退出保护，初始就在边界且未记录时间的情形例外 |
| 世界页需要自身滚动／全景返回 | 使用独立边界状态；向前无后续章节时不循环回首页 |
| 触摸滑动 | 结束时比较起止 `clientY`，距离达到 36px 才按方向启动时间驱动转场 |

这些门控来自 `Wt`、`Yt`、`Qt`、`Ft`，不能仅通过添加一个 `wheel` 监听器替代。[对应源码](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)

## 三、惯性、反向与完成规则

`D3Ws_Xfb.js` 保存响应式状态，渲染循环按帧间隔推进它，而非绑定固定刷新率的递增动画。以下为桌面版本的实际参数；同站其他包存在不同参数，不能混用。[共享状态与推进函数](https://silverpalace.elementagames.com/_nuxt/D3Ws_Xfb.js)

| 参数 | 桌面实际值／作用 |
| --- | --- |
| 输入幅度 | `abs(deltaY)/80`，夹到 `0.85–2` |
| 同向输入增益 | `0.095 × 幅度` |
| 反向输入减益 | `0.016 × 幅度`；已经倒退时另乘 `0.72` |
| 速度范围 | `[-0.045, 0.045]` |
| 时间归一化 | 以 `1000/60 ms` 为基准换算当前帧间隔 |
| 每帧进度步长 | 时间归一化后仍夹到 `[-0.01, 0.01]` |
| 速度衰减 | 前进基数 `0.90`，倒退基数 `0.96`，按帧间隔取幂 |
| 静止阈值 | 速度绝对值小于 `0.0002` 后归零 |
| 进入完成区 | 进度到 `0.8` 后，以每基准帧 `0.006` 自动完成到 `1` |

这使它可以随输入推进、松手减速、在提交章节前倒退；跨过提交点后自动收尾，避免已经换页却停在半张遮罩里。这里的连续性是状态机、时间归一化和着色器共同完成的。

## 四、页面内容和遮罩使用同一个进度，但并非同时出现

`app_pc` 中 `_s=0.1`、`Mt=0.05`、`Rt=0.8`。滚轮切换按以下时序协调真实路由和内容层：[进度观察与路由提交](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)

1. 启动转场，记住起点、终点与待提交路由；当前路由继续存在。
2. 进度到 `0.05` 隐藏旧背景 DOM；到 `0.15` 隐藏旧内容 DOM。
3. 进度到 `0.8` 才执行路由跳转，并等待 Vue 更新，再等一个动画帧。
4. 新内容层恢复；进度到 `0.9` 后恢复新背景 DOM。
5. 到 `1` 清理转场状态；完成后还设置 900ms 的再次切页保护。
6. 提交前反向退回到 `0` 时恢复旧层并撤销这一轮转场。

标题也是双份：旧标题在前半程按进度移动／淡出，新标题在后半程移动／淡入。新闻、影像栏目用线性透明度，其余部分用正弦包络；不能等同于给一个标题统一套 `translateY`。[同一桌面包的标题计算](https://silverpalace.elementagames.com/_nuxt/CA2EmTRG.js)

内容层本身还有 320ms 的透明度、位移和轻微模糊过渡，并在隐藏后禁用指针。这层 DOM 交互管理与底下 GPU 波纹混合各有职责。[页面层 CSS](https://silverpalace.elementagames.com/_nuxt/default_pc.D_7o1Gxp.css)

## 五、展开导航及悬停的真实行为

桌面展开按钮同时绑定“鼠标进入时打开”和“点击时切换”。导航面板鼠标离开时关闭，点击导航条目也关闭。自动化如果直接 `click()`，会先触发进入打开，再点击关闭；所以此前“点击后没看到展开”的截图不能作为没有导航动画的证据。[导航事件代码](https://silverpalace.elementagames.com/_nuxt/CM9fDJKY.js)

面板进入／离开是 220ms 的透明度与纵向偏移。条目悬停时编号和标题横移 `0.42rem`，另一装饰层横移 `0.58rem`；标题还使用纹理裁切文字，属于字体表面处理，而非波纹转场。[导航与悬停 CSS](https://silverpalace.elementagames.com/_nuxt/default_pc.D_7o1Gxp.css)

1920×1080 浏览器实测根字号为 75px，所以条目 `0.42rem` 对应 31.5px、标题字号 `0.72rem` 对应 54px。移植到 AUI 时应按当前窗口和控件大小重设范围，直接复制官网的 `rem` 数字会得到不同尺寸。

## 六、浏览器实测交叉验证

使用独立 Chrome 1920×1080 视口，不登录、不提交站点表单；读取 Nuxt 的公开页面状态，仅保留转场相关字段。记录保存在 `.tools/silver-palace-reference/research-agent/runtime-trace.json`，截图用于检查展开和转场的实际帧。

- `hover()` 后导航面板出现；条目实际变换矩阵的横移分量为 `31.5`；鼠标移出后面板消失。
- 输入 `deltaY=5`，进度仍为 `1`，没有新转场。
- 连续输入 `deltaY=120`：`/home` 在进度约 `0.796` 时仍保留，在约 `0.858` 时已切到 `/roles`。
- 约 `0.858` 时新内容层已恢复、背景层仍隐藏；约 `0.913` 时两层都已恢复。
- 停止输入后收尾到 `1`，转场运行标志解除。实测耗时取决于输入节奏，不能概括成固定几百毫秒。

## 七、透明 Minecraft 菜单的移植建议

以下是基于上述证据的实现建议，不是官网已有 Minecraft 代码：

- 保留“旧内容／新内容／进度／方向／提交点”这组状态，把来源纹理换成透明 UI 渲染目标；只合成 UI 像素，游戏世界不参加缩放、扭曲或换图。
- 正常物品目录滚动先消费输入，到边界才考虑大类切换；输入框、详情滚动区和弹窗具有独立优先级。滚轮幅度和帧间隔须归一化。
- 分类切换、详情展开、分页适合使用波纹擦除；搜索输入和高频键盘移动应及时响应，不应每个字符都触发大幅转场。
- 内容提交点与可点击状态同步；旧内容淡出后不能仍领取旧槽位，新内容尚未绘制时不能提前接收它的点击。
- 导航应支持悬停展开与点击开合，但需避免“先进入打开、同一次点击又关闭”的误关模式。
- 应提供减少动效选项，并在窗口尺寸、GUI 缩放改变后同步重算渲染区域与点击坐标。
