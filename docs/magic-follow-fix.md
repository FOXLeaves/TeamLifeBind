# 随身魔法跟随延迟修复

更新日期：2026-10-20。Minecraft 26.3、Java 26、显示版本 0.1.2、内部构建 0.7.0。

## 原因与修复

吟唱场景每 2 tick 刷新，持续效果通常每 3 tick 刷新。客户端原本在两次场景包之间一直绘制上次收到的位置，因此玩家移动时，随身特效会落后约 100–150 ms 的同步间隔并叠加网络延迟。

Fabric、Forge、NeoForge 现在每帧解析随身锚点，在距离/视锥裁剪、排序、屏幕矩形和 GPU 参数上传之前使用当前玩家的渲染插值位置：

| 效果 | 锚点 |
| --- | --- |
| 吟唱法阵与施法瞬间法阵 | 玩家脚底插值位置 + 0.12 格 |
| 环绕、护盾的持续主体 | 玩家脚底插值位置 + 1 格，保留服务端轴向 |
| 持续引导 | 起点跟眼位，终点保留服务端授权的碰撞位置 |
| 领域、陷阱、召唤点、旋涡、回响 | 固定世界坐标 |
| 已离身弹道、瞬时射线/冲撞路径、命中和消散 | 保留服务端事件坐标 |

第一人称采用与原版相机相同的 `xo/yo/zo` 插值；第三人称与其他玩家采用实体模型的 `xOld/yOld/zOld` 插值。这两组坐标可能不同，不能混用。时间采样对应相机或该玩家的原版暂停/冻结规则；刚生成的实体直接使用当前坐标。

客户端只改变视觉几何，场景缓存保留原始包内容。伤害、碰撞、魔力、同步包格式与服务器更新频率保持。玩家实体暂未加载、已移除或来自其他世界时，回退到包内几何并遵循原有清理和 TTL。

## 验证方式

使用 `python scripts/test-magic-renderpearl.py --output .tools/magic-follow-final`，在三端真实 Minecraft/RenderPearl 夹具中通过实际 `MagicScenePayload.accept` 加载场景，注入真实客户端玩家位置与原版时间管理器，再逐帧读回 GPU 图像。

移动测试只每 3 tick 刷新一次场景包，每半个 tick 改变玩家位置，把实际图像与当前插值位置的静态参考图像逐像素比较。旧代码首个移动帧的 RGB 差值和为 **101,517**，触发 `FOLLOW LAG REPRO`；修复后的初次 Fabric 测试中，21 个移动帧全部为 **0**。固定位置效果另外比较，确保没有跟随玩家移动。

原始失败日志为 `.tools/magic-follow-red-ready/fabric/render.log`，初次通过日志为 `.tools/magic-follow-green-initial/fabric/render.log`。最终每端 **42 个移动或边界场景，最大像素差 0**，每端 **1,213 项断言**通过；同时保留每端 300/300 法术可见检查。覆盖第一/第三人称、世界冻结但玩家移动、暂停、引导的两端语义、缺失/移除/异世界玩家、新生成实体、瞬移、原始场景不被改写和先跟随后裁剪。固定位置对照含领域、陷阱、召唤、标记、弹体、环爆、命中与消散。

可复跑失败对照：`python scripts/test-magic-renderpearl.py --platform fabric --negative-follow-control --output .tools/magic-follow-negative`。它只在隔离副本停用逐帧锚点解析，应以 `FOLLOW LAG REPRO` 断言和退出码 1 失败。最终日志在 `.tools/magic-follow-final/{platform}/render.log`；对照日志在 `.tools/magic-follow-negative/negative-follow-fabric/render.log`。夹具使用真实生产渲染器与 GPU，场景仍为可控合成测试；实际联机网络与其他光影模组的组合需游戏内试玩。

本次移除随身位置等待网络包造成的额外拖尾。远端玩家本身仍受原版实体插值与网络影响；引导终点仍按服务端同步更新，并未承诺所有特效或转向都没有网络延迟。

## 安装

替换发行包中对应加载器的客户端 JAR；联机实例建议客户端与模组服务端使用同批文件。显示版本沿用 0.1.2，应按本批文件更新时间和发行校验值区分。Paper 没有使用这条客户端着色器路径。
